# Game Design Document (GDD) v0.2

> World Sim - 국가 대항 시뮬레이션

---

## 0. 문서 메타

| 항목 | 내용 |
|------|------|
| 버전 | v0.2 |
| 작성일 | 2024-01-19 |
| 변경 이력 | v0.1 → v0.2: TurnDecision/Snapshot 분리, Score 모델 추가, UGC 모더레이션, 이벤트 데이터 드리븐 |

### 용어 정의

| 용어 | 정의 |
|------|------|
| **Turn** | 게임의 시간 단위. 1일 = 1턴 |
| **TurnDecision** | 유저가 턴에 제출하는 입력 (예산 배분, 정책 선택) |
| **TurnSnapshot** | 정산 후 생성되는 턴 결과 스냅샷 (스탯, 이벤트, 점수) |
| **GameSession** | User + Season + Nation 인스턴스. 1유저 = 1국가/시즌 |
| **Nation** | 세션 단위의 국가 인스턴스 (템플릿 기반 생성) |
| **UGC** | User Generated Content (챌린지, 정책 덱, 맵 시드) |
| **Season** | 게임 주기 (4주 또는 8주) |
| **Score** | 복합 점수. 리더보드 순위 결정 기준 |

## 1. 게임 개요

### 1.1 컨셉
- **비동기 국가 운영 시뮬레이션**: 1일 = 1턴
- **경쟁 프레임**: 국가(팀) 정체성 기반의 시즌 리더보드
- **차별점**: UGC로 메타가 돌며 참여가 유지됨

### 1.2 타겟 유저
- **10~15분/일** 플레이 선호 유저
- **경쟁(리더보드)** + **빌드/전략 공유**를 즐기는 유저
- 전략 시뮬레이션 장르 팬

### 1.3 핵심 경험
- **매일 3~5개 의사결정**으로 국가를 성장시키는 감각
- **데일리 챌린지/정책 덱/맵 시드** UGC로 메타가 돌며 참여가 유지됨
- **시즌 리더보드**에서 경쟁하며 순위 상승의 성취감

## 2. 핵심 게임 루프

### 2.1 1일 1턴 구조 (비동기)

```
┌─────────────────────────────────────────────────────────────┐
│  1. 턴 오픈 (유저 입력)                                      │
│     └─ TurnDecision 제출: 예산 배분 + 정책 선택              │
│                                                             │
│  2. 정산 단계 (배치 Job, 자정 KST)                           │
│     └─ 모든 TurnDecision 처리 → TurnSnapshot 생성            │
│                                                             │
│  3. 피드백 단계                                              │
│     └─ 결과 리포트, Score 반영, 리더보드 업데이트             │
└─────────────────────────────────────────────────────────────┘
```

**TurnDecision (유저 입력)**
```json
{
  "sessionId": "uuid",
  "turnNumber": 5,
  "budget": { "economy": 30, "welfare": 20, "research": 20, "military": 15, "diplomacy": 15 },
  "activePolicies": ["policy-1", "policy-2", "policy-3"],
  "diplomacyActions": [{ "type": "TRADE", "targetSessionId": "uuid" }]
}
```

**TurnSnapshot (정산 결과)**
```json
{
  "sessionId": "uuid",
  "turnNumber": 5,
  "statsSnapshot": { "gdp": 350, "military": 55, ... },
  "events": [{ "definitionId": "event-1", "effects": {...} }],
  "scoreChange": 120,
  "totalScore": 1540
}
```

### 2.2 예산 배분 시스템

| 항목 | 영향 스탯 | 설명 |
|------|----------|------|
| 경제 (economy) | GDP, 산업력 | 경제 성장, 생산력 |
| 복지 (welfare) | 행복도, 인구 | 사회 안정, 인구 증가 |
| 연구 (research) | 연구 생산량 → 기술 레벨 | 기술 발전 |
| 군비 (military) | 군사력 | 억지력, 방어력 |
| 외교 (diplomacy) | 외교력, 국제 신뢰도 | 국제 영향력 |

**제약**:
- 합계 100%
- 최소 각 5%, 최대 각 50%
- 정책 카드에 의한 수정 가능

### 2.3 이벤트 시스템 (데이터 드리븐)

**개념 분리**:
- **EventDefinition**: 이벤트 정의 (어드민/시스템이 관리)
- **EventInstance**: 발생한 이벤트 기록 (GameSession에 귀속)

**EventDefinition 구조**:
```json
{
  "id": "financial-crisis",
  "name": "금융위기",
  "category": "ECONOMY",
  "triggers": {
    "conditions": [
      { "stat": "gdp", "operator": ">", "value": 500 },
      { "stat": "happiness", "operator": "<", "value": 40 }
    ],
    "baseProbability": 0.15
  },
  "effects": {
    "gdp": -50,
    "happiness": -10,
    "multipliers": { "gdpGrowth": 0.8 }
  },
  "duration": 3
}
```

**트리거 조건**:
| 타입 | 설명 | 예시 |
|------|------|------|
| 스탯 범위 | 특정 스탯이 범위 내 | GDP > 500 |
| 정책 활성 | 특정 정책 사용 중 | 긴축 정책 활성 시 |
| 외교 상태 | 외교 관계 조건 | 제재 상태일 때 |
| 맵 시드 | 시드 파라미터 | 재난 빈도 높음 |
| 기본 확률 | 무조건 확률 | 5% 기본 |

### 2.4 외교 시스템

**관계 스탯**:
- **우호도**: 양자 관계 (-100 ~ +100)
- **국제 신뢰도**: 전체 평판 (0 ~ 100)

**외교 행동**:
| 행동 | 비용 | 효과 |
|------|------|------|
| 동맹 제안 | 외교력 20 | 상호 방어, 무역 보너스 |
| 무역 협정 | 외교력 10 | GDP 보너스 (양측) |
| 경제 제재 | 외교력 30 | 대상 GDP -15%, 신뢰도 -5 |
| 불가침 | 외교력 5 | 전쟁 방지 |
| 외교 투자 | GDP 5% | 외교력 +10 |

### 2.5 분쟁/전쟁 시스템 (MVP 최소화)

**MVP 범위**:
- 전쟁은 **"분쟁 이벤트"** 수준으로만 구현
- 직접 점령/병참 없음
- 경제 제재 + 군사적 압박 + 이벤트로 간접 표현

**후속 확장 (v2+)**:
- 전구(전장) 단위 점령
- 병참/보급 시스템

### 2.6 승리 조건

**시즌 승리**: Score 기준 랭킹

**보조 목표 (배지)**:
- 경제 강국: GDP 1위
- 기술 선진국: 기술 레벨 1위
- 외교 대국: 국제 신뢰도 1위
- 철의 장막: 군사력 1위

## 3. 국가 시스템

### 3.1 스탯 목록 (9개)

| 카테고리 | 스탯 | 타입 | 설명 | 범위 |
|---------|------|------|------|------|
| 경제 | GDP | Stock | 국가 총생산 규모 | 100-∞ |
| 경제 | 산업력 | Flow | 턴당 GDP 증가 기여 | 10-200 |
| 경제 | 자원 | Stock | 천연자원 보유량 | 0-100 |
| 기술 | 기술 레벨 | Stock | 누적 기술 수준 | 1-10 |
| 기술 | 연구 생산량 | Flow | 턴당 기술 레벨 기여 | 10-100 |
| 군사 | 군사력 | Stock | 억지력/방어력 | 10-200 |
| 사회 | 인구 | Stock | 국민 수 (만 단위) | 100-50000 |
| 사회 | 행복도 | Stock | 국민 만족도 | 0-100 |
| 외교 | 외교력 | Stock | 외교 행동력 | 0-100 |

**별도 관리**:
- 국제 신뢰도: 외교 평판 (0-100)

### 3.2 Flow vs Stock 정의

```
Flow (플로우)          →     Stock (스톡)
────────────────────────────────────────
연구 생산량 (턴당)     →     기술 레벨 (누적)
산업력 (턴당)          →     GDP (누적/성장)
```

**스탯 업데이트 공식**:
```
기술 레벨 += 연구 생산량 / 100
GDP += 산업력 × (1 + GDP 성장률)
```

### 3.3 초기 방향 설정

| 방향 | 초기 보너스 | 트레이드오프 |
|------|------------|-------------|
| 산업 강국 | 산업력 +20%, GDP +10% | 행복도 -5 |
| 금융 허브 | GDP 성장률 +5%, 외교력 +10 | 군사력 -10% |
| 군사 대국 | 군사력 +20%, 방어 보너스 | GDP 성장 -5% |
| 기술 선진국 | 연구 생산량 +30% | 자원 소모 +10% |

**원칙**:
- 국가 편향 없음 (Team Korea = Team USA = 동일 템플릿)
- 방향 선택만으로 차별화

## 4. Score 모델 및 리더보드

### 4.1 Score 산식

```
Score = 경제점수 + 기술점수 + 외교점수 + 안정점수 - 리스크패널티

경제점수 = (GDP / 100) × 0.35
기술점수 = (기술레벨 × 50) × 0.25
외교점수 = (외교력 + 국제신뢰도) × 0.20
안정점수 = (행복도 + 인구/1000) × 0.20
리스크패널티 = 전쟁상태 × 50 + 제재상태 × 30
```

**가중치 조정**: 시즌별 메타에 따라 어드민 파라미터로 조정 가능

### 4.2 스노우볼 방지

**상위국 페널티**:
- 내부 리스크 이벤트 확률 증가 (부패, 불만)
- 외교 견제 강화 (제재 대상 가능성)
- 유지비 증가 (GDP 대비 비용)

**하위국 캐치업**:
- 동맹 수혜 강화
- 기술 도입 비용 감소
- 특정 전략 보너스 (역전 챌린지)

## 5. UGC 공통 파이프라인

### 5.1 UGC 생명주기

```
draft → published → (신고 시) under_review → hidden/banned
                  ↘ (정상) active
```

| 상태 | 설명 |
|------|------|
| DRAFT | 작성 중 (비공개) |
| PUBLISHED | 공개됨, 플레이 가능 |
| UNDER_REVIEW | 신고 접수, 검토 중 |
| HIDDEN | 임시 숨김 |
| BANNED | 영구 차단 |

### 5.2 생성/배포/플레이/채점

| 단계 | 설명 | 마찰도 |
|------|------|--------|
| 생성 | 템플릿 기반 입력 | 30초~3분 |
| 배포 | 코드/링크 공유 | 1클릭 |
| 플레이 | 동일 조건 재현 (seed/params) | 동일 경험 |
| 채점 | Score 또는 목표 달성 | 명확한 기준 |

### 5.3 모더레이션 원칙

**금지 콘텐츠**:
- 국가/민족 비하 및 혐오
- 정치적 선동
- 폭력 조장
- 성인 콘텐츠

**신고/제재 단계**:
1. 유저 신고 (UGCReport)
2. 자동 필터 (키워드)
3. 어드민 수동 검토
4. 제재 결정 (ModerationAction)

## 6. UGC 3종 상세 스펙

### 6.1 데일리 챌린지 (Challenge)

**템플릿 구조**:
```json
{
  "title": "자원 빈국의 역전",
  "description": "자원 없이 30턴 내 GDP 1위",
  "seasonScope": "S1",
  "seed": 12345,
  "startNationTemplate": "balanced",
  "constraints": [
    { "type": "STAT_LOCK", "stat": "resource", "value": 0 },
    { "type": "BUDGET_CAP", "category": "military", "max": 20 }
  ],
  "winConditions": [
    { "type": "STAT_REACH", "stat": "gdp", "value": 1000 }
  ],
  "turnLimit": 30,
  "scoringOverride": null
}
```

**제약 조건 타입**:
| 타입 | 설명 |
|------|------|
| STAT_LOCK | 스탯 고정 (변경 불가) |
| STAT_CAP | 스탯 상한 |
| BUDGET_CAP | 예산 항목 상한 |
| DIPLOMACY_BAN | 외교 행동 금지 |
| POLICY_BAN | 특정 정책 금지 |

**승리 조건 타입**:
| 타입 | 설명 |
|------|------|
| STAT_REACH | 스탯 목표 도달 |
| SCORE_REACH | 점수 목표 도달 |
| SURVIVE | N턴 생존 |
| RANK_REACH | 리더보드 순위 도달 |

### 6.2 정책 덱 (PolicyDeck)

**덱 구성**: 8장 고정

**카드 카테고리**:
| 카테고리 | 예시 카드 |
|---------|----------|
| 경제 (ECONOMY) | 수출 장려, 긴축 재정, 국내 투자 |
| 사회 (WELFARE) | 기본소득, 출산 장려, 교육 투자 |
| 기술 (TECH) | R&D 집중, 기술 도입, 특허 보호 |
| 군사 (MILITARY) | 징병제, 방위 산업, 핵억지 |
| 외교 (DIPLOMACY) | 적극 외교, 고립주의, 다자외교 |
| 리스크 (RISK) | 치안 강화, 반부패, 언론 통제 |

**우선순위**:
- 1-8 순서로 실행
- 충돌 시 높은 우선순위 우선

### 6.3 맵 시드 (MapSeed)

**파라미터**:
```json
{
  "seed": 12345,
  "resourceRichness": "SCARCE",
  "oilBias": 0.2,
  "mineralBias": 0.5,
  "tradeAccess": "HIGH",
  "disasterRate": "NORMAL"
}
```

**프리셋**:
| 프리셋 | 설명 |
|--------|------|
| balanced | 균형 잡힌 시작 |
| resource_poor | 자원 빈국 |
| landlocked | 내륙국 (무역 페널티) |
| island | 섬나라 (방어 보너스) |

## 7. 시즌 & 리더보드

### 7.1 시즌 주기

| 단계 | 기간 | 설명 |
|------|------|------|
| 프리시즌 | 3일 | 튜토리얼, 테스트 |
| 정규 시즌 | 4주 (28턴) | 본 경쟁 |
| 종료/정산 | 1일 | 최종 순위, 보상 지급 |

### 7.2 리더보드 종류

| 리더보드 | 기준 | 갱신 주기 |
|---------|------|----------|
| 전체 Score | 종합 점수 | 일일 |
| 경제 부문 | GDP + 산업력 | 일일 |
| 기술 부문 | 기술 레벨 | 일일 |
| 외교 부문 | 외교력 + 신뢰도 | 일일 |
| UGC 제작자 | 플레이 수 × 완주율 - 신고율 | 주간 |

### 7.3 보상 체계

| 등급 | 조건 | 보상 |
|------|------|------|
| Diamond | 상위 1% | 전용 국기 스킨, 시즌 배지, 제작자 뱃지 |
| Platinum | 상위 5% | 국기 스킨, 시즌 배지 |
| Gold | 상위 20% | 프로필 프레임 |
| Silver | 상위 50% | 칭호 |

**원칙**: 꾸미기/명예만, P2W 없음

## 8. 밸런스 원칙

### 8.1 수치 조정
- 모든 밸런스 수치는 **파라미터화** (하드코딩 금지)
- 어드민 대시보드에서 실시간 조정 가능

### 8.2 과금 원칙 (향후)
- 과금 = 꾸미기/편의
- 승패에 직접 영향 없음
